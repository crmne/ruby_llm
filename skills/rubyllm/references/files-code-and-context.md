# Files, code execution, and context

Read this when the model works on files, runs code, or tool results get long.

- To let the model work on files, use `with_file_store` (or the agent `file_store` macro) rather than writing file tools or pasting text into prompts (2.2): the model lists, searches, reads, writes, and edits files with its own tools. It sees attachments on the latest question in full, except a text file longer than the inline limit, which goes as its start, then one line for each until it reads them again. `chat.file_store` is the store. Pass a folder path or `:memory` to choose the store. Text, Word, Excel, and PowerPoint files are read as text out of the box: register `config.file_converters` for more, such as `RubyLLM::FileStore::Converters::OCR.new` for PDFs and images. A result the store kept in a file names it in `spilled_path` (read it with `chat.file_store.read(path)`), and the start of a long attachment is `partial?`: read those rather than matching RubyLLM's wording (2.2). To keep tool results from overflowing the context window, set `config.context_budget = { per_result: 0.25, per_request: 0.7 }` in the initializer, which the install generator writes for new Rails apps, rather than overriding private methods to trim requests (2.2). Every chat and agent uses it, so rewriting the generated ChatAgent is safe; `with_context_budget` or the agent `context_budget` macro overrides it, and `nil` turns it off.
- Use `with_thinking`, `with_caching`, `with_compaction`, and `with_citations` without arguments to enable them and `false` to disable them. They reject `nil`. Read the relevant guide for supported options and model requirements. Set caching once, not per provider: a fallback leaves out the caching options its provider has no use for, and a persisted chat sends a stable cache key of its own, so do not pass `key:` only when the model is OpenAI (2.2).
